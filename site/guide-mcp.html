PRISE EN MAIN · MODE AVEC AGENT IA

Votre caméra observe.
Votre agent vous éclaire.

Connectez NovaGuard à un client compatible MCP pour interroger les passages enregistrés. Commencez avec la lecture seule : la surveillance reste autonome sur le téléphone.

Android 16 minimumUn ordinateur sur le même Wi-FiUn client MCP HTTP avec en-têtes

Ce guide suit la branche main. Les versions publiées plus anciennes peuvent proposer moins d’options. Choisir une version compatible avec les fonctions souhaitées.

01 / SUR VOTRE ANDROID

Préparez une première détection.

Installez NovaGuard, autorisez la caméra et lancez la surveillance depuis l’application ouverte à l’écran. Faites un passage dans le champ, puis vérifiez sa présence dans Historique. Vous disposerez ainsi d’un événement réel à consulter avec votre agent.

Connectez le téléphone et l’ordinateur au même réseau Wi-Fi de confiance. Le client doit accepter un serveur MCP HTTP et un en-tête Authorization ; vérifiez cette possibilité dans sa version actuelle.

L’agent ne lance pas la détection.

Le modèle embarqué et l’enregistrement continuent sur Android. MCP donne accès aux données ; il ne remplace pas la caméra ni le détecteur.

02 / DANS LES RÉGLAGES

Activez le serveur et la lecture.

En haut de Réglages, le bloc Assistant IA (MCP) affiche l’état du serveur. La capture des réglages montre « Serveur éteint : aucun assistant ne peut se connecter ». Le bouton Voir les services MCP permet de consulter les capacités sans activer le serveur.

Le plus court : dans le bloc Assistant IA (MCP), touchez Connecter un assistant. L’application demande où tourne l’assistant (ce téléphone, le Wi-Fi ou le cloud), lequel, puis donne l’adresse ou la configuration à copier et indique quand elle a reçu sa première requête. Un agent installé sur le même téléphone, dans Termux par exemple, n’a besoin d’aucune clé pour lire. Les étapes ci-dessous détaillent la même chose à la main.

  1. Ouvrez Réglages → Avancé → Serveur MCP. Si le serveur est déjà actif, son bloc est également visible directement dans les réglages.
  2. Générez un clé d’accès de lecture, puis activez le serveur MCP. Sans clé, le serveur reste limité au téléphone (127.0.0.1) et n’est pas joignable depuis l’ordinateur.
  3. Conservez Autoriser le pilotage et Vue en direct pour l’agent désactivés pour ce premier essai.
  4. Copiez l’adresse affichée : le port par défaut est 8081 et le chemin se termine par /mcp. Utilisez cette adresse, qui peut changer avec le Wi-Fi.
Chiffrer la connexion avec HTTPS +

Si votre version dispose de Chiffrer les connexions, activez cette option. Copiez le certificat d’autorité PEM depuis NovaGuard, comparez son empreinte SHA-256 à celle affichée sur le téléphone, puis ajoutez cette autorité de confiance au client.

Les clients Node peuvent utiliser NODE_EXTRA_CA_CERTS avec le chemin du PEM ; redémarrez le client dans l’environnement qui définit cette variable. D’autres clients utilisent le magasin de certificats du système : suivez leur documentation. Ne désactivez pas la vérification TLS pour contourner une erreur.

Si HTTPS est désactivé, l’adresse commence par http:// et le jeton comme les données circulent sans chiffrement. Réservez ce mode à un réseau local de confiance. N’exposez pas le port sur Internet.

03 / DANS VOTRE CLIENT MCP

Importez la configuration.

La méthode à privilégier : dans NovaGuard, utilisez Copier la config JSON ou le QR code, puis importez ces informations dans le client. Le QR code contient le clé : traitez-la comme un mot de passe et évitez de le partager dans une capture.

Pour un client qui accepte le format mcpServers avec url et headers, le modèle est le suivant. Dans Cursor, la configuration MCP se place par exemple dans .cursor/mcp.json pour un projet, ou dans les réglages MCP du client.

EXEMPLE À ADAPTER · AUCUNE CLÉ RÉELLE 
{
  "mcpServers": {
    "novaguard": {
      "url": "https://192.168.1.42:8081/mcp",
      "headers": {
        "Authorization": "Bearer REMPLACER_PAR_LA_CLE_DE_LECTURE"
      }
    }
  }
}

L’adresse ci-dessus est fictive : remplacez-la par celle copiée depuis votre téléphone, avec le bon protocole HTTP ou HTTPS. Remplacez aussi la clé. Cette configuration suppose un client qui prend en charge ce format ; les autres clients demandent les mêmes informations dans leur interface.

Ce que la 1.1 ajoute à la consultation.

Avec novaguard_get_configuration, votre agent peut vérifier le nombre de zones ignorées, l’option d’image dans l’alerte et les heures calmes. Demandez par exemple : « Les heures calmes sont-elles actives et combien de zones sont ignorées ? » Ces informations sont consultables ; leur modification reste dans les réglages du téléphone.

Activez ou rechargez le serveur dans le client. Vous devriez voir les outils de lecture, notamment novaguard_get_status, novaguard_search_events et novaguard_get_event_frames. Les noms visibles peuvent inclure un préfixe propre au client.

04 / UNE PREMIÈRE QUESTION

Partez d’un passage enregistré.

« Vérifie l’état de NovaGuard, puis montre-moi la dernière détection et examine les images disponibles. Signale ce que tu ne peux pas vérifier. »

L’agent consulte l’état, retrouve l’événement et demande des images du clip. Une vidéo absente peut être remplacée par sa vignette, si elle existe. Vérifiez sa réponse avec l’historique sur le téléphone.

Comprendre la nuit

« Que s’est-il passé cette nuit ? Distingue personnes et animaux et indique les périodes où la caméra était en défaut. »

Vérifier l’installation

« Consulte les diagnostics et le stockage. La caméra est-elle en état de détecter un passage maintenant ? »

Si votre client affiche les prompts MCP, essayez night_report, review_alerts ou diagnose_camera. Une absence d’événement ne prouve pas l’absence d’activité si la caméra ou l’analyse était indisponible.

05 / VOUS GARDEZ LA MAIN

Choisissez ce que l’agent peut voir et faire.

Les autorisations MCP, séparées dans les réglages
Accès Ce qu’il permet Votre action
Lecture Événements, statistiques, images des clips, diagnostics. Activer MCP et utiliser la clé de lecture sur le réseau local.
Vue en direct Demander une image actuelle avec get_live_frame, pendant la surveillance. Activer son interrupteur distinct ; désactivé par défaut.
Pilotage Démarrer/arrêter, régler sensibilité et seuils, conserver ou annoter un passage, acquitter une alerte de déplacement. Autorisation distincte et clé dédiée avec durée choisie. Chaque action est journalisée.

Le démarrage par l’agent exige que l’application soit à l’écran et dispose de la permission caméra. L’agent ne peut pas supprimer un clip ni changer la rétention. Vous pouvez couper le pilotage depuis sa notification et désactiver le serveur dans les réglages.

Avec une IA distante, les données peuvent sortir du téléphone.

NovaGuard conserve son traitement local. Le client IA reçoit cependant les métadonnées et images qu’il demande et peut les transmettre à son fournisseur. Vérifiez ses règles de confidentialité avant d’accorder l’accès.

BESOIN D’UN COUP DE MAIN ?

Les vérifications utiles.

Le client ne trouve pas le téléphone +

Vérifiez le même Wi-Fi, l’adresse affichée, le port et le chemin /mcp. Une adresse 127.0.0.1 n’est accessible que sur le téléphone : générez une clé pour ouvrir la lecture au réseau local. Certains réseaux invités isolent les appareils entre eux.

Le client refuse le certificat HTTPS +

Vérifiez que l’autorité PEM du téléphone est approuvée par le client et que son empreinte correspond. Utilisez l’adresse actuelle affichée. Une réinstallation de l’application crée une nouvelle autorité : réimportez le certificat correspondant.

La lecture marche, mais le pilotage est refusé +

La clé de lecture n’autorise pas le pilotage. Activez son interrupteur, vérifiez que sa clé dédiée n’a pas expiré et actualisez la configuration du client. Pour démarrer la caméra, ouvrez NovaGuard à l’écran.

La dernière vidéo ou le direct ne s’affiche pas +

Le média peut avoir été supprimé par la rétention. Pour analyser un clip, l’agent doit demander ses images avec get_event_frames, plutôt que charger le MP4 entier. Le direct exige son autorisation distincte et une surveillance en cours ; une scène vide n’est pas un résultat de diagnostic.
